项目：`/share/latent2/vcrm_v1002_phase12`。与旧 VCRM 工程验收输出隔离；模型和原始发布数据只读复用，prepared 数据独立生成。

## 固定输入

- TransMem 作者版本：`6d7a6127967ad44482c958b555d8c83bfb75e9b9`，下载完整源码并逐文件核对 Git blob。
- delta-Mem 协议依赖：`bb6e99bb6b3a94ddae7f9b4743bfd8ae37e98675`，核对 LoCoMo protocol 和评分依赖源码。

- TransMem-qwen3-4B-D4：revision `85ba1010eb226e312e208940180bb60424a2cb79`，step 1250，注入层 32/33/34/35，4 个 HM 槽。
- 全部模型 safetensors 与 checkpoint 对照 HF 元数据 SHA256 验证，LoCoMo/LongMemEval 原始数据对照已下载清单验证。

## 运行时适配

V100 使用 FP16 + SDPA。作者发布代码调用 `past_key_values`，本机 Transformers 4.51.3 的 Qwen3DecoderLayer 接受 `past_key_value`。独立 runtime adapter 仅转换参数名，不修改作者源码、模型权重、提示词或评分函数。

未适配时，作者三项 KV-cache 测试失败；适配后作者 36 项 tests 全通过。自有 22 项 tests 通过。CPU 线程设置为 1，降低多模型加载时的线程竞争。

## 阶段 1

`upstream_locomo_full_v1002`：物理 GPU 4/5/9，三片共 1540 原始问题；全历史、类别 1–4、greedy、max_answer_tokens=50、无 prompt 截断。只调用作者 `eval_locomo.py` 和 `merge_locomo_shards.py`。

合并后检查完整原始 question keys、类别、无重复/遗漏，并使用同一官方协议函数重新计算逐题 F1。核查完成不等于宣称与论文数值完全一致。

论文 Table 1 Qwen3-4B TransMem 参考：overall 54.11、multi-hop 52.04、temporal 45.62、open-domain 20.64、single-hop 61.87，单位百分数。完整实测后逐项记录差异；不得根据中间分数调整解码、评分或提示词。

```bash
ssh v100-2
cd /share/latent2/vcrm_v1002_phase12
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  ./run_experiments.sh --stage reproduce --gpus 4,5,9 --run-name upstream_locomo_full_v1002
./run_experiments.sh --stage status --run-name upstream_locomo_full_v1002
```

同 run name、同代码/config、同分片数可从官方逐题进度续跑。切换分片数需新目录，GPU 编号可改变但不能使用忙卡。

## Streaming 诊断前置

`diagnostics/check_reader_parity.py` 检查实际 GPU 的缓存长度 5→6、chunked/one-shot HM 差异、单/双会话 custom injection 与作者入口的 token-id 等价性。只使用合成输入，不使用评测标签，不构成 benchmark 成绩。

对话 session ID 采用不含 evidence 标记的 opaque ordinal；时间相同的会话保持原始顺序。LongMemEval 完整供应历史协议使用 `Current date`，而不是强加会屏蔽未来证据的 `As of`；TempLAMA 显式历史查询仍使用 `As of`。

## 阶段 2

只运行 A `transmem_streaming`，LongMemEval cleaned-S 全部 500 题。不训练 C/D，不进行 VCRM 正式对比。

阶段 2 首轮使用 **无容量淘汰** 的诊断 baseline，仍持久化并在查询前重载 memory store，保留 32 latent slots 读取上限，无原始历史查询回读。现有约 88–105 KB 三点预算对 A 都只能保留一条约 82 KB 会话，不能用于判断 reader 是否正常；后续再单独做容量诊断。

`--baseline-no-eviction` 使用 1 TiB 哨兵上限，不是实际分配 1 TiB；报告真实文件 bytes，不能当作同预算对照实验。

```bash
# 必须先完整核对阶段 1 并通过 reader parity，再显式批准。
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  ./run_experiments.sh --stage stream --dataset longmemeval --split test \
  --methods transmem_streaming --baseline-no-eviction --gpus all \
  --run-name lme_streaming_no_eviction --accept-reproduction
./run_experiments.sh --stage score --baseline-no-eviction --run-name lme_streaming_no_eviction
./run_experiments.sh --stage report --baseline-no-eviction --run-name lme_streaming_no_eviction
```

评分使用用户提供的服务和 Qwen3.5-9B judge，采用 LongMemEval 官方提示词，凭证只存在权限 600 的 `.env`。API 正/反控制已验证，不称为 GPT-4o 官方分数。

答案生成结束后才将 gold evidence 与 retained/selected IDs 离线关联；这些标注不进入 ingestion/query/retrieval。报告完整 Accuracy、knowledge-update、temporal-reasoning 细分，以及证据丢失/检索遗漏/选中仍错误的计数。最后一项仍混合 latent 编码、reader 和语言推理错误，不能仅凭该标签断言具体原因。
